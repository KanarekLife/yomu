# 0016. Sync: last-writer-wins records over a small server or a shared folder

- Status: accepted
- Date: 2026-11-12

## Context

Reading happens on a phone and on a desktop. Each device has its own SQLite
library, so progress, books, settings and paid-for translations didn't follow
the reader. Some people want a hosted service, and others already sync files
with Syncthing and want no server at all.

## Decision

**What syncs:** books (keyed by the EPUB's fingerprint), which also carries
the reading position, last-read time and deletion; the EPUB files; the
settings blob, *including the LLM API key* (by choice); and cached
translations. Dictionaries do not sync: they are large and the one-click setup
reinstalls them.

**Records and merging** (`reader-core/src/sync.rs`). Each record carries an
`updated_at` in Unix milliseconds, and the newer record wins.
- A position or sentence number is sent as "n-th text sentence", so importer
  differences such as illustration steps (ADR-0015) don't shift it.
- A deleted book is a tombstone record. A deletion only wins against older
  changes, so a book read elsewhere after it was deleted stays.
- A synced book whose EPUB isn't on this device yet waits in `sync_pending`,
  together with its translations. They are applied once the file arrives.
- `set_settings` ignores writes that don't change anything, so a device that
  merely opened Settings never overrides newer settings from elsewhere.

**Transports**, both built on the same records:
- **Yomu server** (`crates/yomu-server`): axum + PostgreSQL. It has built-in
  accounts (argon2 password hashes), per-device bearer tokens (stored as
  SHA-256 hashes), a `POST /api/v1/sync` endpoint that applies the client's
  changes and returns everything with `rev > since`, and EPUB files stored as
  `bytea`. A server-rendered admin panel at `/admin` manages users and
  devices. The first admin comes from `YOMU_ADMIN_USER` and
  `YOMU_ADMIN_PASSWORD`.
- **Folder** (Syncthing, Nextcloud, …): each device writes only its own
  `devices/<device-id>.json` with its full state, written to a temporary file
  and then renamed. It reads every other device's file and merges them, and
  shares EPUBs as `books/<key>.epub`. With a single writer per file, the sync
  tool never sees conflicts.
- On Android, folders in shared storage need **All files access**
  (`MANAGE_EXTERNAL_STORAGE`), which is requested from the Sync screen. It is
  acceptable because Yomu is sideloaded, not published on Play.

**When it syncs:** at start-up, every 5 minutes, when the app goes to the
background, shortly after importing or deleting a book, after leaving the
reader, 15 s after a settings change, and from *Sync now*.

## Consequences

- No merge UI and no history: two devices reading the same book at the same
  time keep whichever position was saved last. That is acceptable for a
  reading position.
- The server holds the user's API key and books. It is self-hosted, so the
  operator is the user.
- Clocks matter for last-writer-wins, but only between edits made seconds
  apart.
- Hosting: kogr.dev runs the server image `ghcr.io/kanareklife/yomu-server` with
  a `yomu` database on the shared CloudNativePG cluster (see that repo).
